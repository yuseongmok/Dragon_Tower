1. 적용 결과와 확인 방법

Unity에서 프로젝트 갱신 후 Assets/Data/Dragon2.asset의 Evolution Forms Stage 2를 확인한다.

기존 정적 최종형 이미지도 삭제하지 않고 보존했다.

3. 디자인과 애니메이션
첨부 제피르 진화 컨셉의 오른쪽 아래 성체를 기준으로 내장 image_gen을 사용했다.
긴 몸과 다리, 성숙한 작은 얼굴, 크게 뻗은 날개, 가슴 깃털, 긴 갈래 꼬리를 표현했다.
민트/청록 몸색, Deep Teal/남색/보라 그림자, 밝은 날개막, 황금 눈과 귀 계보를 유지했다.
기본형 또는 중간형을 확대하지 않고 최종형 전용 포즈를 생성했다.
시트 경계를 넘는 포즈는 이미지 생성 도구로 여백을 보정했다.
Unity 수입은 기존과 동일하게 Point, PPU 100, 최대 512, Mipmap 없음, 압축 없음이다.
각 상태 4프레임. Idle 1.20초 / Attack 0.24초 / Skill 0.40초 / Dodge 0.42초 /
Hit 0.24초 / Death 0.60초 및 각 프레임별 시간은 기본형에서 그대로 복사했다.
별도의 Animator Controller, Character Controller, Animation Event 체계를 만들지 않았다.
실제 프로젝트는 공용 Sprite 프레임 재생기를 사용하므로 여기에 새 Animation Set만 연결했다.
전체 생성/보정 프롬프트: ZephyrFinalPrompts.txt.

4. 재사용한 시스템과 Anchor 검수
DragonData 단계 선택 -> Animation Set 로드 -> 기존 BattleAnimation 재생 경로를 그대로 사용한다.
현재 Pipeline에는 진화별 개별 VFX Anchor 필드가 없다.
기존 playerHome/enemyHome 및 공격·스킬 호출 기준점은 변경하지 않았다.
최종형 24포즈의 발 위치를 기존 지면 기준점에 맞추는 offsets만 새 데이터에 저장했다.
displayScale은 생성 시트별 빈 여백 차이를 보정하는 값이며 성장 비율을 대신하는 확대가 아니다.
Idle displayScale=1, 기존 256x256 캐릭터 배치 사각형과 부모 위치를 유지했다.
기본 공격, 스킬 집결/전달, 투사체, 피격, 지면 기준을 Play Mode 캡처에서 확인했다.
최종형의 날개·꼬리가 적이나 HP/아이템/스킬 버튼을 지속적으로 가리지 않는다.
새 Anchor 필드나 VFX Prefab 변경 없이 연결 가능했다. 기본/중간형 Anchor와 Scale은 그대로다.
HP/공격력 배율은 0(기존 단계 배율 사용), 기본 스킬 override 없음. 밸런스 변경 없음.
질풍강타, 바람칼날, 질풍참, 귀참, 단천을 동일 데이터와 동일 VFX로 재사용한다.
단천의 화면 연출, 피해 시점, 무적, 취소 처리도 그대로다.

5. Pipeline 두 번째 검증 결과
런타임 Controller/Skill Script/HUD 복사: 0개. 캐릭터 전용 런타임 조건문 추가: 0개.

회귀 검사도 같은 코드를 stage 1/2에 재사용했다.

Resources 참조가 즉시 언로드됨을 보장하는 스트리밍 구조는 아니며 그런 시스템을 추가하지 않았다.
