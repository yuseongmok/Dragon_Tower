기능 분리
기존 Firebase는 WebGL JavaScript 동적 SDK와 AccountBridge.jslib로 연결되어 있었으며 Unity 패키지 의존성은 없었습니다.
클라우드는 인증/닉네임/온라인 랭킹용, 드래곤/도전/이름/아이템/증강은 ProfileStore의 기기 저장용입니다.
OnlineFeatures.Enabled=false, firebase-config enabled=false, WebGL 시작 페이지의 Firebase bridge 로드 제거,
WebAccountService 요청 차단, 랭킹 제출/조회 차단으로 이번 버전에서 서버 초기화와 통신을 중지했습니다.
관련 코드/설정/Functions/규칙은 재도입을 위해 보존했습니다. 실제 Firebase 프로젝트와 클라우드에는 변경을 하지 않았습니다.

저장 이관
Firebase SDK를 초기화하지 않고 브라우저 IndexedDB의 마지막 로그인 UID만 로컬에서 읽습니다.
토큰은 Unity에 전달하거나 서버로 보내지 않습니다. 이 UID로 기존 계정별 PlayerPrefs 저장 위치를 찾습니다.
기존 계정 .Account.<hash> 원본을 보존하고 .Offline.<hash>에 복사합니다.
이미 이관한 위치는 다시 덮어쓰지 않습니다. 로컬 기본 기록도 있으면 사용자에게 둘 중 하나를 선택하도록 표시합니다.
선택된 위치는 DragonTower.Profile.v1.OfflineStore에 저장됩니다. 선택 뒤에는 인증 캐시 조회도 필요 없습니다.
읽기 실패/손상/저장 위치 불명은 안내하고 자동 초기화하지 않습니다.
전환 직전 기기 저장 .A/.B도 .BeforeOffline.A/.B 키에 한 번 보관합니다.
기존 프로필 버전, 드래곤 ID/이름, 도전 저장 구조는 유지하고 필드를 추가했습니다.

개인 기록
bestScore, bestFloor, bestBond를 독립 최고값으로 저장합니다.
bestScoreRun에는 최고 점수를 얻은 동일 도전의 드래곤 ID/종류/사용자 지정 이름을 보존합니다.
신규 기록은 사망 또는 기존 80층 완주 확정 시에만 갱신됩니다. 로비 복귀/이어하기는 종료가 아닙니다.
기존 버전에서 이미 저장한 최고 수치는 낮추지 않고 이관합니다.
기존 저장에 대응하는 파트너 정보가 없으면 '이전 기록 · 파트너 정보 없음'으로 표시하며 추정하지 않습니다.
로컬 닉네임은 기존 값 우선이며, 없는 경우 기기에 남은 닉네임 캐시를 사용합니다.
온라인 전송 대기 기록은 보존만 하고 추가 적재/전송하지 않습니다.

UI
첫 실행/재실행 모두 로그인 없이 로비로 진입합니다. 아직 드래곤이 없는 첫 실행은 로비에서 기존 부화 흐름으로 연결됩니다.
로비 배경과 드래곤 위치를 유지하고 '나의 탑 기록' 패널을 추가했습니다.
계정 삭제/온라인 랭킹 버튼 대신 로컬 닉네임과 기존 업적/도전 기록을 사용합니다.
명시적 게임 초기화 버튼도 선택한 로컬 저장에만 적용하며 이전 Firebase 계정 원본을 대상으로 하지 않습니다.
