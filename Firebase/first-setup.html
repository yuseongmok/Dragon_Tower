Firebase 첫 설정 안내

현재 게임은 조련사 캐릭터·꾸미기 없이 플레이어 닉네임만 설정합니다. 기존 이름은 유지되며, 로그인 후 신규 계정은 닉네임 설정으로, 기존 계정은 로비로 이동합니다. 이미 게시한 보안 규칙은 다시 바꾸지 않아도 됩니다. 외형 필드는 이전 저장과의 호환성만을 위해 내부에 남아 있습니다.

게임 쪽 연결 코드와 조련사 UI는 준비됐습니다. 아직 실제 Firebase 프로젝트에 연결하거나 규칙을 배포하지 않았습니다. 설정 전에도 로컬 플레이는 가능합니다.

1. 개발용 프로젝트 만들기

  1. Firebase Console에 Google 계정으로 로그인합니다.
  2. 프로젝트 만들기 → 예: Dragon Tower Dev. 처음에는 개발용 프로젝트 하나를 만드세요. 출시 때는 별도 프로젝트를 사용합니다.
  3. Google Analytics는 이번 기능에 필수가 아닙니다.
  4. 프로젝트 생성 후 웹 앱 추가 </> → 앱 이름 Dragon Tower Web Dev → 앱 등록.
  5. 표시되는 firebaseConfig 내용을 복사합니다. 이 설정은 공개 웹 연결 정보이며, 서비스 계정 비밀 키와 다릅니다.

여기까지 하신 뒤 firebaseConfig를 이 채팅에 붙여주시면 연결 설정을 도와드릴 수 있습니다. 서비스 계정 JSON, 개인 키, 관리자 키는 보내지 마세요.

2. 로그인 방식 켜기

  1. Build → Authentication → 시작하기.
  2. Sign-in method에서 Anonymous(익명)와 Email/Password(이메일/비밀번호)를 활성화합니다.
  3. Settings → Authorized domains에 실제 게임 주소의 도메인을 추가합니다. 개발 테스트용 localhost가 없다면 직접 추가합니다.
  4. 가능하면 이메일 열거 방지와 비밀번호 정책을 활성화합니다. 클라이언트는 8자 이상을 안내하고 Firebase의 더 강한 정책을 따릅니다.

플레이어는 이메일 없이 아이디·비밀번호로 가입합니다. 아이디는 영문으로 시작하는 영문·숫자·_ 4~20자이며 대소문자를 구분하지 않습니다. Firebase 내부에서는 아이디를 예약된 가상 주소로 매핑하므로 Email/Password 기능은 켜야 합니다. 가상 주소는 메일 발송에 사용하지 않습니다. 아이디가 중복되면 게스트 UID를 변경하거나 자동 병합하지 않습니다.

3. Firestore 만들고 잠그기

  1. Build → Firestore Database → 데이터베이스 생성.
  2. 프로덕션 모드로 시작합니다. 실제 이용자와 가까운 위치를 신중하게 선택합니다.
  3. Rules 탭에서 프로젝트의 Firebase/firestore.rules 내용을 붙여넣고 게시합니다.
  4. Rules Playground 또는 Emulator로 본인 UID 읽기/쓰기 허용, 다른 UID 접근 거부, 재화·점수 변경 거부를 확인합니다.

규칙 파일은 작성됐지만 아직 서버에 배포·검증되지 않았습니다. 공개 전에 반드시 게시와 검증을 마쳐야 합니다. 기본 허용 규칙으로 공개하지 마세요.

4. 게임과 연결하기

Assets/WebGLTemplates/DragonTower/firebase-config.js에 웹 앱 설정값을 넣고 enabled: true로 변경한 뒤 WebGL을 다시 빌드합니다. 개발은 environment: 'development', 출시는 별도 프로젝트 설정과 'production'을 사용합니다. 빌드 후 같은 이름의 설정 파일도 배포 폴더에 포함됩니다.

실제 게임 주소는 HTTPS로 제공하세요. 테스트용 로컬 서버도 사용할 수 있습니다. 파일을 더블클릭한 file:// 주소에서는 로그인과 WebGL을 검증하지 않습니다.

웹 설정에는 관리자 비밀 키를 넣지 않습니다. Firebase JS SDK 13.0.0은 공식 CDN에서 요청 시 불러옵니다. 향후 출시 전 SDK 번들링·App Check·사용량 경보도 검토하세요.

5. 무엇이 저장되나요?

  • 서버: users/{uid}의 조련사 이름, 기본형, 피부색, 머리, 기본 의상/빈 액세서리, 선택 드래곤 종류 ID, 생성/수정 시각, 스키마와 수정 버전.
  • 기기: 기존 드래곤 보유·별명·도전·아이템·증강·업적·기록. 이번 단계에서 서버로 업로드하거나 복구하지 않습니다.
  • 계정 연결: 익명 계정에 아이디·비밀번호를 연결하면 같은 UID와 기기 저장을 유지합니다.
  • 다른 계정 로그인: 기기 저장을 계정별로 분리합니다. 이전 저장은 삭제하지 않습니다.
  • 기존 진행 가져오기: 사용자가 선택할 때만 로그인 전 기기 진행을 빈 계정 저장에 복사합니다. 원본 유지, 기존 계정 진행 덮어쓰기 금지.
  • 충돌: 저장 버전이 다르면 자동 저장 중단. 재시도하거나 확인 후 서버 프로필을 선택합니다. 기기 게임 진행과 자동 병합하지 않습니다.
  • 기록: 남아 있는 기존 기록을 활용하고 이후 최고 유대·점수를 기기에 보존합니다. 과거에 이미 사라진 기록은 복원하지 못합니다.

6. 실제 연결 후 확인할 순서

  1. 게스트 시작 → 조련사 생성 → Firestore에 UID 문서가 생기는지 확인.
  2. 새로고침 → 같은 UID·조련사 복구.
  3. 아이디 연결 → UID와 조련사·도전 기록 유지 확인.
  4. 다른 브라우저에서 아이디 로그인 → 조련사 프로필 복구 확인. 드래곤/도전은 아직 클라우드 대상이 아님.
  5. 같은 프로필을 두 탭에서 수정 → 충돌 안내 확인.
  6. 네트워크 끊기 → 저장 실패 안내·로컬 초안 보존·재시도 확인.
  7. 다른 UID 읽기/쓰기 및 영구 재화·랭킹 점수 쓰기 거부 검증.

실제 프로젝트가 아직 없어 Firebase 로그인·계정 연결·실서버 저장·보안 규칙 배포는 미검증입니다.

공식 안내: 웹 앱 등록 · 익명 로그인 · 계정 연결 · 필드 보안 규칙

선택 기능: 복구 이메일

가입에는 이메일이 필요하지 않습니다. 로그인 후 계정 화면 → 복구 이메일 등록 (선택)에서 이메일을 입력하고, 받은 6자리 번호를 10분 안에 확인합니다. 인증된 주소만 비밀번호 찾기에 사용됩니다. 로그인 아이디는 변하지 않습니다. 보안을 위해 로그인 5분 안에 등록하세요.

아이디 로그인은 기본 Firebase 설정으로 가능하지만, 복구 이메일은 다음 서버 배포가 추가로 필요합니다. 아직 배포/실발송하지 않았습니다. Cloud Functions와 메일 제공 업체에는 별도의 요금/설정이 필요할 수 있으므로 지금 자동으로 유료 서비스를 개설하지 않았습니다.

  1. Firebase Functions 환경과 SMTP 메일 발송 계정을 준비합니다. SMTP 비밀번호는 채팅이나 게임 파일에 넣지 마세요.
  2. Firebase CLI의 Secret Manager에 TRAINER_SMTP 비밀값을 저장합니다. JSON 필드: host, port, secure, from, auth.user, auth.pass. 서버만 이 값을 읽습니다.
  3. Firebase/functions에서 의존성을 설치하고 Firebase 폴더에서 firebase deploy --only functions:trainerRecovery를 실행합니다. 실제 프로젝트를 먼저 지정해야 합니다.
  4. Firebase App Check에 웹 앱을 등록하고 reCAPTCHA v3 사이트 키와 허용 도메인을 설정합니다. 함수는 유효한 App Check 요청만 허용합니다.
  5. firebase-config.js에 appCheckSiteKey를 넣고 recoveryEnabled: true로 변경한 후 WebGL을 다시 빌드합니다.

서버는 인증번호 만료·5회 시도 제한·재전송 제한·계정/IP별 요청 제한을 적용합니다. 복구 주소와 인증번호 해시는 클라이언트가 읽거나 수정할 수 없는 별도 문서에 보관합니다. 인증번호는 한 번만 사용할 수 있습니다. 비밀번호는 별도 DB에 저장하지 않고 Firebase Authentication이 관리합니다.

검증 순서: 아이디 중복/대소문자 → 게스트 연결 UID 유지 → 이메일 없이 재로그인 → 선택 이메일 인증 → 비밀번호 찾기 → 잘못된/만료/재사용 인증번호 거절 → 다른 UID 문서 접근 차단. 실제 서버 설정 전에는 이 항목들을 통과한 것으로 간주하지 않습니다.

Firebase 계정 관리 · Firebase 비밀번호 재설정 링크

계정 삭제 버튼 추가 후 필요한 설정

Firestore → 규칙에서 최신 Firebase/firestore.rules 전체 내용을 다시 붙여넣고 게시해야 합니다. 이전 규칙에서는 계정 삭제가 안전하게 거부되며 일반 로그인은 유지됩니다.

설정 → 계정 삭제 → 아이디 계정은 현재 비밀번호 재입력 → ‘삭제’ 입력 → 계정 영구 삭제. Firebase 계정과 프로필·복구 이메일 및 현재 기기의 해당 계정 저장을 제거합니다. 다른 계정의 저장과 계정 연결 전 독립 로컬 기록은 삭제하지 않습니다. 다른 기기의 로컬 파일을 원격으로 삭제하는 기능은 없습니다.

서버 문서 삭제에 실패하면 인증 계정은 삭제하지 않습니다. 서버 문서 삭제 후 인증 삭제가 실패하면 ‘삭제 진행 중’을 표시하고 재시도합니다. 재생성 방지용 최소 삭제 표식은 UID 경로에 남습니다. 실제 사용자 계정을 검수 목적으로 삭제하지 않습니다.
